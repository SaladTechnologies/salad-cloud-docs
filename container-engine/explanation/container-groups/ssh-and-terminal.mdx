title: 'SSH & Terminal Access'

_Last Updated: October 19, 2026_

SaladCloud provides two ways to access a shell inside your running container instances: a web-based terminal directly in
the Portal, and SSH access for connecting from your local machine or other SSH clients.

## SSH Access

Use SSH to open a shell on a running container instance after adding your public key in the SaladCloud Portal.

### 1. Create or Obtain an SSH Key

If you already have an SSH key pair, you can skip this step. To check for existing keys:

```bash
ls -la ~/.ssh/
```

Look for files named `id_ed25519.pub` or `id_rsa.pub`. SaladCloud accepts Ed25519 (`ssh-ed25519`) and RSA (`ssh-rsa`)
keys only, so an ECDSA key such as `id_ecdsa.pub` won't work.

To create a new SSH key:

```bash
ssh-keygen -t ed25519 -C "you@example.com"
```

This creates `~/.ssh/id_ed25519` (private key) and `~/.ssh/id_ed25519.pub` (public key). Your public key will look
similar to this:

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIHKz8vGk9XpFmEqTcvN7LMfPxWkR5yJQ2nBdW1cLmK4p you@example.com
```

### 2. Copy Your Public Key

```bash
cat ~/.ssh/id_ed25519.pub
```

### 3. Add the Key in the Portal

There are two ways to access the SSH key settings:

- Click your username in the upper-right corner and select **SSH Keys**, or
- Click **SSH Keys** in the left sidebar menu

Paste your public key into the field and save it.

<Note>
  Each user holds one SSH public key, and saving a new key replaces the existing one. If you connect from more than one
  machine, use the same key pair on each. A public key can belong to only one user, so teammates each need their own key
  pair. Saving a key that another user has already registered fails with "SSH key already registered".
</Note>

### 4. Connect to a Container Instance

1. Open your container group in the Portal and click on a running instance.
2. You will see an SSH command displayed in a text box above the terminal. Command will look something like this:

   ```bash
   ssh root@<hostname> -p <port>
   ```

3. Copy the command and paste it into your terminal.

4. The Portal also displays the key fingerprint for verification, so you can confirm you're connecting with the correct
   key.

SSH automatically tries default key files from `~/.ssh/` (such as `id_ed25519` and `id_rsa`), so the command shown in
the Portal works without modification for most users.

If your key has a custom name or is stored in a non-standard location, add the `-i` flag to specify your key name and
location:

```bash
ssh -i ~/.ssh/my_custom_key root@<hostname> -p <port>
```

The SSH command appears once the instance is scheduled on a node, which can take a little longer than the instance
reaching the Running state.

### Connecting as Another User

The user in the SSH command must exist in your container image. `root` always works. To connect as another user, create
it in your image (for example, with `useradd` in your Dockerfile) and replace `root` in the command. Sessions start in
`/bin/sh`, so your image must include it.

### Running One-Off Commands

You can run a single command without opening an interactive session:

```bash
ssh root@<hostname> -p <port> -- nvidia-smi
```

The connection always reports exit code `1` for one-off commands, even when the command succeeds, and the command's
errors are mixed into its standard output. Check the output instead of the exit code, especially in scripts.

### Copying Files

SFTP is supported, so `sftp` and modern `scp` (which uses SFTP by default in OpenSSH 9 and later) can copy files to and
from an instance:

```bash
scp -P <port> ./input.txt root@<hostname>:/data/
scp -P <port> root@<hostname>:/data/output.txt ./
```

Files you copy into an instance are stored on its ephemeral disk and are lost when the instance is reallocated or
recreated.

## Terminal Access

The web-based terminal provides quick access directly from your browser without any SSH setup.

1. Open the [SaladCloud Portal](https://portal.salad.com) and navigate to your container group.
2. Click on a running instance.
3. Click on the **Terminal** tab to open an interactive shell.

The terminal opens `/bin/sh` as `root`. If it doesn't connect, see
[Troubleshooting](/container-engine/how-to-guides/troubleshooting#my-container-group-is-running-but-i-cant-access-it-with-the-web-terminal).
